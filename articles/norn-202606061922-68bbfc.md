## はじめに

気づいたら稼働中のSaaSが16本になっていた。

いちいち全部自分で設計・実装・リリースしたわけではない。AIが自律的にアイデアを評価して、コードを書いて、デプロイまでやるシステムを作っていたら、気づいたらそうなっていた、という話だ。

この記事では「どういうシステムを作ったのか」「実際に何が動いているのか」を、誇張なしで書いていく。

---

## 課題：個人開発者の時間は有限すぎる

マイクロSaaSの面白いところは、「小さな課題を解決するツールが意外と売れる」という点だ。フリーランサーが日々直面する細かい困りごと、個人事業主が確定申告でつまずく瞬間、webdevがAIワークフローを組もうとして設定の煩雑さに挫折する瞬間——こういうニッチなペインは無数にある。

ただし、それをひとつひとつ手で実装していたら一生終わらない。

アイデアを思いついてから「リリースできる状態」にするまでの作業量を考えると、月に1本出せれば良いほうだ。そのペースでは、100個の仮説のうち売れるものを見つけるのに何年かかるか分からない。

**「仮説検証の速度」こそがマイクロSaaS開発のボトルネックだ**、というのが出発点だった。

---

## 解決策：AIに「企画〜デプロイ」を任せるパイプラインを作る

やったことをざっくり言うと、以下のパイプラインを構築した。

1. **ペイン収集エージェント** — SNS・掲示板・フォーラムをクロールして「解決されていない困りごと」を収集・スコアリング
2. **アイデア評価エージェント** — 市場規模・競合・実装難易度を自動評価してスコアを出す
3. **実装エージェント** — スコアが閾値を超えたアイデアをもとにコードを生成・テスト
4. **リリースエージェント** — LP生成・デプロイ・決済連携まで自動で行う

全体のオーケストレーションにはn8nを使っていて、各エージェントはClaude APIを叩いている。

yaml
# n8nワークフローの概略（一部抜粋）
pain_collection:
  trigger: cron(0 8 * * *)  # 毎朝8時
  steps:
    - scrape_sources  # Reddit, Zenn, はてブ等
    - score_pain_points  # LLMでスコアリング
    - store_to_db

idea_evaluation:
  trigger: pain_score > 70
  steps:
    - market_research_agent
    - competitor_check_agent
    - implementation_cost_estimate
    - if total_score > 80: trigger_build


このパイプラインが動き始めてから、月に3〜5本のペースでSaaSが生まれるようになった。

## 実際に動いているもの（正直なところ）

現在16本が稼働中で、月次の売上は合計すると数万円規模になっている。代表的なものをいくつか挙げると：

- **FreelancePainPollBot**（¥4,350/月）：フリーランサーの「どのツールでも解決されていない細かい困りごと」を可視化・集約するボット
- **WorkflowNagBot**（¥2,850/月）：MCPやn8n連携の設定が煩雑でつまずくwebdevやフリーランサー向けのワークフロー補助ツール
- **FreelancerToolPainTracker**（¥1,800/月）：フリーランサーの生産性を静かに損なうペインポイントを追跡するツール

正直に言うと、16本のうち売上がほぼゼロのものも複数ある。AIが「良さそう」と判断してもマーケットに刺さらないケースは普通にある。それでいい、というのがこのアプローチの前提だ。

**打席数を増やすことで、当たりを引く確率を上げる**という戦略なので、失敗コストを下げることの方が重要だ。

## 実装で詰まったポイント

いくつか正直に書いておく。

**LPの品質が安定しない問題**
コード生成は比較的安定してきたが、LPのコピーライティングはまだ人間がレビューする必要がある。AIが生成した文章は「正確だが刺さらない」ことが多い。

**ペイン収集のノイズが多い**
SNSから拾ってくる「困りごと」の中には、実際には課金するほどではないものが大量に混じっている。スコアリングのプロンプトを何度もチューニングしたが、完璧ではない。

python
# ペインスコアリングのプロンプト（現在のバージョン）
SYSTEM_PROMPT = """
あなたはマイクロSaaSの市場調査アナリストです。
以下のペインポイントを100点満点でスコアリングしてください。

評価基準：
- 再現性（同じ課題が繰り返し発生するか）: 40点
- 支払い意欲（無料ツールで我慢していないか）: 35点
- 実装可能性（1〜2週間で作れるか）: 25点

必ずJSON形式で返してください。
{"score": 0-100, "reason": "理由", "suggested_solution": "解決案"}
"""


このプロンプトに至るまでに、かなりの試行錯誤があった。

## まとめ

AIを使った自律的なSaaS量産システムは、「作って終わり」ではなく「仮説検証を高速で回し続けるインフラ」として機能している。

今のところ16本稼働、そのうちいくつかは月数千円規模の売上を出している。大きな成功とは言えないが、このシステムがなければ3本も作れていなかったと思う。

日本のSaaS市場は2026年時点で138億ドル規模（13.5% CAGR）と言われており、特にフリーランサーや個人事業主向けの日本語SaaSはまだ手薄な領域が多い。英語圏で普及しているツールが日本語未対応のまま放置されているケースも目立つ。

小さく作って、たくさん試して、当たりを探す。そのサイクルを速くする仕組みを持っていることが、個人開発者にとって今一番の武器になると感じている。
