## はじめに

現在、個人で16本のマイクロSaaSを稼働させている。月額収益はツールによってまちまちで、¥1,350〜¥4,350/月という規模感だ。

最初の数本は「なんとなく困ってそう」な課題をテーマに作ったが、リリースしてみると反応がまばらだったり、そもそも需要がズレていたりした。特に日本語市場は英語圏と異なる課題感があり、Indie HackersやProductHuntの情報をそのまま転用できないケースも多い。

**「次に何を作るか」の意思決定に、自分が一番時間を使っていた。**

そこで、市場調査のプロセスをある程度自動化してみた。今回はその仕組みと気づきを共有する。

---

## 課題：市場調査が属人的すぎた

自分がやっていた調査は、だいたい以下のような手作業だった。

- RedditやX（旧Twitter）で「つらい」「困ってる」系の投稿を手動で検索
- Zennやnoteで「個人開発 失敗」「フリーランス 作業効率」などを週1で巡回
- 競合SaaSのレビューをG2やCapterraで掘る

問題は**再現性がないこと**。気が向いたときしかやらないので、良いシグナルを見逃していた。

たとえば `FreelancePainPollBot`（¥4,350/月）は、フリーランサーの「細かい困りごと」を集約するツールだが、このアイデアは偶然X上で拾った投稿がきっかけだった。もっと体系的にやれば、もっと早く同様のニーズを発見できたはずだと今でも思う。

---

## 解決策：キーワード監視＋LLMによる需要スコアリング

やったことはシンプルで、**定期クローリング → テキスト収集 → LLMでスコアリング → Notionへ通知** というパイプラインを組んだ。

構成はこんな感じ：


[Cron: 毎朝6時]
  ↓
[Python スクリプト]
  ├─ Reddit RSS / X API 検索
  ├─ Zenn / note フィード取得
  └─ 競合SaaSのレビューページスクレイプ
  ↓
[OpenAI API (GPT-4o-mini)]
  → 各投稿を「課題の明確さ・市場規模感・既存解決策の有無」で1〜5点スコアリング
  ↓
[Notion API]
  → スコア3以上のみデータベースに追加


LLMへのプロンプトは以下のような形にしている：

python
prompt = f"""
以下の投稿を読み、マイクロSaaSのアイデアとしての有望度を評価してください。

評価基準:
1. 課題が具体的か（1-5点）
2. 日本語圏で未解決の問題か（1-5点）
3. 月額課金に耐えうるペインか（1-5点）

投稿:
{post_text}

出力形式（JSONのみ）:
{{"score": 合計点, "reason": "1〜2文の理由", "idea_hint": "想定されるSaaSの概要"}}
"""


GPT-4o-miniを使うことでコストを抑えつつ、1日あたり50〜100件処理してもAPIコストは月数百円程度に収まっている。

---

## 実装してみて分かったこと

**良かった点：**

- 週1の手作業が「朝のNotionチェック5分」に変わった
- `SoloTaxReceiptBot`（¥1,350/月）のアイデアは実際にこのパイプライン経由で拾ったもの。「確定申告 API 挫折」というキーワードクラスタが繰り返し出てきた
- 英語圏では解決済みなのに日本語版がない、というギャップを発見しやすくなった（Japan SMB × English-only toolの組み合わせ）

**限界・正直な話：**

- LLMのスコアはあくまで「可能性の示唆」であって、需要の確証ではない
- X APIの無料枠はかなり厳しくなっており、月$100のBasicプランに入らないと実用的なクロールは難しい
- スコアが高くても、実際に作ってみると「競合が少ない＝市場が小さい」だったケースもあった

現在稼働中の16本を振り返ると、**月¥3,000を超えるツールは「フリーランサーが毎週つまずいている操作」に絞ったもの**が多い。AIワークフロー系（`WorkflowNagBot`：¥2,850/月）や税務系などは特にその傾向が強い。

---

## まとめ

市場調査の自動化で変わったのは、**「良さそうなアイデアを見逃さなくなった」こと**に尽きる。0→1の確率が上がったわけではないが、インプットの量と質が安定した。

個人開発でネックになるのは「何を作るか」の判断コストだと思っている。コードを書く時間は確保できても、調査の習慣化は意外と難しい。それを仕組みに落とし込むだけで、少し楽になった。

興味があれば試してみてほしい。まずはRSSとOpenAI APIだけで動く最小構成から始めるのがおすすめだ。
