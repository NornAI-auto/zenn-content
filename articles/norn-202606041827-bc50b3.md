## はじめに

個人でSaaSを複数運営していると、「コードは書けるのに、お金の受け取りだけは手動」という状態がずっと続いていた。

請求書をGoogleスプレッドシートで管理して、振込確認してから手動でアカウントを有効化する。最初の1〜2本はそれでなんとかなったが、今は16本のSaaSを稼働させていて、さすがに限界が来た。

この記事では、PythonとStripeを使って**支払い受付→アカウント発行→サブスクリプション管理を全自動化**した実装の流れを、実際に動いているシステムをベースに紹介する。

---

## 課題：手動オペレーションのコスト

自分が運営しているSaaSのうち、`FreelancePainPollBot`（¥4,350/月）や`WorkflowNagBot`（¥2,850/月）あたりは月次の新規ユーザーがそこそこ来る。

最初は「決済システム作るより先にプロダクトを磨け」という考えで手動運用していた。が、実際に困ったのは以下の3点：

- **支払い確認→アカウント有効化のタイムラグ**（深夜に申し込まれたら翌朝まで放置）
- **解約・プラン変更の追跡ミス**（スプレッドシートとの乖離が地味に起きる）
- **レシートや請求書の発行漏れ**（`SoloTaxReceiptBot`を自分で使えよという話）

合計すると月に数時間、集中力を削られていた。コードを書く時間に使いたかった。

---

## 解決策：StripeのWebhookを起点にする

Stripeには**Webhook**という仕組みがある。支払い完了・失敗・解約など、あらゆるイベントをHTTPで自分のサーバーに通知してくれる。

これを受け取るエンドポイントをPythonで立てて、イベント種別に応じた処理を実行する、というのが基本構成だ。

構成はシンプルにした：


[Stripeイベント]
    ↓ Webhook
[FastAPI エンドポイント]
    ↓
[処理ルーター]
    ├─ checkout.session.completed → アカウント発行
    ├─ invoice.payment_failed    → ユーザー通知
    └─ customer.subscription.deleted → アカウント停止


インフラはRailwayに置いていて、月数百円で動いている。

---

## 実装：Webhookを受け取るコード

以下が実際に使っているWebhookハンドラーの骨格だ（簡略化済み）。

python
from fastapi import FastAPI, Request, HTTPException
import stripe
import os

app = FastAPI()
stripe.api_key = os.environ["STRIPE_SECRET_KEY"]
WEBHOOK_SECRET = os.environ["STRIPE_WEBHOOK_SECRET"]

@app.post("/webhook")
async def stripe_webhook(request: Request):
    payload = await request.body()
    sig_header = request.headers.get("stripe-signature")

    try:
        event = stripe.Webhook.construct_event(
            payload, sig_header, WEBHOOK_SECRET
        )
    except stripe.error.SignatureVerificationError:
        raise HTTPException(status_code=400, detail="Invalid signature")

    event_type = event["type"]
    data = event["data"]["object"]

    if event_type == "checkout.session.completed":
        customer_email = data.get("customer_details", {}).get("email")
        await provision_user(customer_email, data["subscription"])

    elif event_type == "invoice.payment_failed":
        customer_id = data.get("customer")
        await notify_payment_failed(customer_id)

    elif event_type == "customer.subscription.deleted":
        customer_id = data.get("customer")
        await deactivate_user(customer_id)

    return {"status": "ok"}


ポイントは`stripe.Webhook.construct_event`でシグネチャ検証をしっかり行うこと。これをサボると第三者からの偽リクエストで誤発火する。

`provision_user`の中では、DBにユーザーレコードを作成してAPIキーを生成し、SendGrid経由でウェルカムメールを送る処理が入っている。支払い完了から約3秒でユーザーが使い始められる状態になる。

## 実際に運用してみてわかったこと

**良かった点：**
- 深夜の申し込みでも即座にアカウントが発行される
- 解約処理の漏れがゼロになった
- Stripeのダッシュボードを見れば売上・解約率が一目でわかる

**ハマった点：**
- Webhookは同じイベントが**2回来ることがある**（冪等性の考慮が必須）
- テスト環境と本番環境でWebhook Secretが別なので、環境変数の管理を間違えると本番でエラーが出る
- `invoice.paid`と`checkout.session.completed`の両方でアカウント発行処理を書いてしまい、重複発行が起きた（初月は両方飛んでくる）

冪等性の対策として、`subscription_id`をユニークキーにしてDBにUPSERTする方式にしてから問題は起きていない。

## まとめ

StripeのWebhook × Pythonは、個人開発者がSaaSの収益化を自動化するうえで最もコスパが良い構成だと感じている。

Stripeのドキュメントは日本語対応もしていて品質が高い。Webhookのテストは`stripe listen --forward-to localhost:8000/webhook`コマンドでローカルでも簡単に試せる。

手動オペレーションで時間を溶かしているなら、まずWebhookエンドポイントを1本作るところから始めてみると良いと思う。自分のように複数SaaSを回す場合は特に、この自動化が効いてくる。

最初の実装は半日もあれば動くものができる。プロダクトを作る時間を、請求書確認に使うのはもったいない。
