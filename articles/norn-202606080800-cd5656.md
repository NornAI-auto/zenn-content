## はじめに

個人開発でSaaSを作っても、「決済周りの実装が面倒で後回しにしている」という人は多いんじゃないかと思う。自分もそうだった。

現在16本のマイクロSaaSを稼働させているが、最初の数本はStripe連携を手動で組んでいたため、新しいサービスを出すたびに同じコードを書き直していた。`FreelancePainPollBot`（月¥4,350）や`WorkflowNagBot`（月¥2,850）あたりは収益も安定してきたが、立ち上げ時の決済実装コストが毎回ボトルネックになっていた。

そこで「Stripeの初期設定からWebhook処理・サブスクリプション管理まで」をPythonで全自動化するテンプレートを作った話を書く。

---

## 課題：毎回同じことを繰り返していた

新しいSaaSを立ち上げるたびに、以下の作業を手動でやっていた。

- Stripeダッシュボードで商品・価格を手動作成
- Webhook エンドポイントの登録
- `checkout.session.completed` イベントの処理
- サブスク解約時のユーザーステータス更新

`SoloTaxReceiptBot`（月¥1,350）を出したとき、またゼロから実装し直して「さすがにこれは自動化すべきだ」と気づいた。

---

## 解決策：Stripe APIとWebhookをPythonで一括管理

方針はシンプル。

1. **商品・価格の作成をスクリプト化**（ダッシュボード操作ゼロ）
2. **FastAPIでWebhookエンドポイントを共通化**
3. **イベントごとの処理をdictで管理**して拡張しやすくする

## 実装

### STEP 1：商品と価格をコードで作る

python
import stripe
import os

stripe.api_key = os.environ["STRIPE_SECRET_KEY"]

def create_product_and_price(name: str, amount: int, interval: str = "month") -> dict:
    """Stripeに商品と価格を作成して返す"""
    product = stripe.Product.create(
        name=name,
        metadata={"created_by": "auto_setup"},
    )
    price = stripe.Price.create(
        product=product.id,
        unit_amount=amount,  # 円単位（JPY）
        currency="jpy",
        recurring={"interval": interval},
    )
    print(f"Created: {product.name} / price_id={price.id}")
    return {"product_id": product.id, "price_id": price.id}

# 使用例
create_product_and_price("WorkflowNagBot", 2850)
create_product_and_price("FreelancePainPollBot", 4350)


これを `setup_stripe.py` として保存しておき、新サービスを追加するときはここに1行足すだけ。ダッシュボードを開く必要がなくなった。

### STEP 2：Webhookを共通エンドポイントで受ける

python
from fastapi import FastAPI, Request, HTTPException
import stripe
import os

app = FastAPI()

WEBHOOK_SECRET = os.environ["STRIPE_WEBHOOK_SECRET"]

# イベントごとの処理をdictで管理
EVENT_HANDLERS = {
    "checkout.session.completed": handle_checkout_completed,
    "customer.subscription.deleted": handle_subscription_cancelled,
    "invoice.payment_failed": handle_payment_failed,
}

@app.post("/webhook/stripe")
async def stripe_webhook(request: Request):
    payload = await request.body()
    sig_header = request.headers.get("stripe-signature")

    try:
        event = stripe.Webhook.construct_event(
            payload, sig_header, WEBHOOK_SECRET
        )
    except stripe.error.SignatureVerificationError:
        raise HTTPException(status_code=400, detail="Invalid signature")

    handler = EVENT_HANDLERS.get(event["type"])
    if handler:
        handler(event["data"]["object"])

    return {"status": "ok"}


`EVENT_HANDLERS` に関数を登録するだけで処理が増やせる構造にしている。新しいSaaSが増えても、このファイルに関数を追加するだけで対応できる。

## 実際に運用してみてわかったこと

**良かった点：**
- 新サービスの決済実装が15分以内に終わるようになった
- Webhookの処理漏れがなくなった（以前は `checkout.session.completed` を二重処理するバグを出していた）
- Stripeダッシュボードでの手動ミスが減った

**注意点：**
- Webhookのエンドポイント登録だけはStripeダッシュボード上で一度だけ手動設定が必要
- `STRIPE_WEBHOOK_SECRET` はエンドポイントごとに異なるので環境変数の管理に注意
- JPYは少数通貨（zero-decimal currency）なので `unit_amount` に100を掛けなくていい（USDと混同しないこと）
